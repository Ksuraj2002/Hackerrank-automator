## Classwork: Last Digit of a Number
**Problem Statement**
A billing system needs the final digit of an invoice number to pick a verification counter.

Given a non-negative integer `N`, print only its last digit. For `N = 45983` the last digit is `3`.

You do not need a loop for this. Dividing by `10` in integer arithmetic throws away the last digit, and the remainder operator keeps exactly that digit: `N % 10` is the answer. Watch what happens when the last digit is `0` - `100 % 10` is `0`, and `0` is the correct output, not an empty line.

**Input Format**
A single line containing one non-negative integer `N`.

**Output Format**
A single line containing the last digit of `N`.

**Constraints**
- `0 <= N <= 10^9`
- Time Complexity: `O(1)`
- Space Complexity: `O(1)`

45983

## Classwork: Simple Interest
**Problem Statement**
A bank quotes interest on a deposit using the simple-interest formula

```
SI = (P * R * T) / 100
```

where `P` is the principal amount, `R` is the annual rate of interest in per cent, and `T` is the time in years.

Read `P`, `R` and `T` and print the simple interest, rounded to exactly two decimal places.

Two things to be careful about. First, read the values into `double` variables - the rate can be fractional, like `7.5`. Second, dividing by `100` must not be integer division: if all three inputs are stored as `int`, `P * R * T / 100` truncates and the answer comes out wrong. Print with a fixed two decimals, for example `cout << fixed << setprecision(2) << si;`.

**Input Format**
A single line containing three space-separated values: `P` (principal), `R` (annual rate per cent) and `T` (time in years). Any of them may be decimal.

**Output Format**
A single line containing the simple interest, printed with exactly two decimal places.

**Constraints**
- `0 <= P <= 10^7`
- `0 <= R <= 100`
- `0 <= T <= 100`
- Answer must match to two decimal places
- Time Complexity: `O(1)`

**Sample Input 0**
```
1000 5 2
```

**Sample Output 0**
```
100.00

## Homework: Drop the Last Digit
**Problem Statement**
Given a non-negative integer `N`, print the number that remains after its last digit is removed. For `N = 45983` the answer is `4598`.

This is the companion of finding the last digit. Where `N % 10` keeps the last digit, integer division `N / 10` discards it - as long as both operands are integers, C++ throws the fractional part away rather than rounding.

**Input Format**

## Classwork: Grading System: Marks to Message
**Problem Statement**
A school reports a student's performance as a message rather than a letter grade. Given the marks scored by a student, print the matching message using these bands:

```
marks > 90                 -> excellent
80 < marks <= 90           -> good
70 < marks <= 80           -> fair
60 < marks <= 70           -> meets expectations
40 < marks <= 60           -> below par
marks <= 40                -> failed
```

Print the message exactly as written above, in lower case, with no extra punctuation.

Note that every boundary value belongs to the *lower* band: `90` is `good`, not `excellent`, and `40` is `failed`, not `below par`. An else-if ladder handles this naturally - test `marks > 90` first, then `marks > 80`, and so on, so each test only sees values the earlier tests rejected. Writing the bands as independent `if` statements is where this problem usually goes wrong.

**Input Format**
A single line containing one integer, the marks scored by the student.

**Output Format**
A single line containing one of `excellent`, `good`, `fair`, `meets expectations`, `below par` or `failed`.

**Constraints**
- `0 <= marks <= 100`
- Time Complexity: `O(1)`
- Space Complexity: `O(1)`

**Sample Input 0**

95
```

**Sample Output 0**

# Day 6 - Nested if-else & else-if ladder

## Classwork: Make Chocolate (CodingBat)
**Problem Statement**
The CodingBat classic *makeChocolate*. Reference: https://codingbat.com/prob/p191363

You need to make a goal weight of chocolate using small bars of `1` kilo each and big bars of `5` kilos each. Print the **number of small bars** to use, assuming you always use big bars before small ones. Print `-1` if the goal weight cannot be made exactly.

The greedy rule is forced: use as many big bars as fit without overshooting, which is `min(big, goal / 5)` bars. Whatever weight is left must be covered one kilo at a time by small bars - if the remainder exceeds the number of small bars available, the goal is impossible and the answer is `-1`.

With `small = 4`, `big = 1`, `goal = 9`: one big bar covers `5`, leaving `4`, and you have exactly `4` small bars, so the answer is `4`. With `small = 4`, `big = 1`, `goal = 10` the remainder is `5` but only `4` small bars exist, so the answer is `-1`.

**Input Format**
A single line containing three space-separated integers: `small` (count of 1-kilo bars), `big` (count of 5-kilo bars) and `goal` (the weight to make).

**Output Format**
A single line containing the number of small bars to use, or `-1` if the goal cannot be made exactly.

**Constraints**
- `0 <= small <= 1000`
- `0 <= big <= 1000`
- `0 <= goal <= 10^5`
- Time Complexity: `O(1)`

**Sample Input 0**
```
4 1 9
```

**Sample Output 0**
```
4
```

```

```

**Sample Output 1**
```
-1
```
